## Faults that went through, and what would stop them

- `null_amount`: one row with a blank amount. Would be stopped by `not_null` on the amount.
- `amount_in_cents`: one amount sent in cents (x100). Would be stopped by a range test on the amount, or a batch total compared with recent batches.
- `absurd_amount`: one amount of 45,000,000. Would be stopped by a range test on the amount.
- `negative_amount`: one amount flipped negative. Would be stopped by a lower bound on the amount (or an explicit sign rule for refunds).
- `foreign_amount_labeled_home`: one amount in KRW scale, currency unchanged. Would be stopped by a range test per currency, or a batch total compared with recent batches.
- `unknown_currency`: one currency code not in the expected set. Would be stopped by `accepted_values` on the currency code.
- `unknown_category`: one status value never seen before. Would be stopped by `accepted_values` on the status.
- `future_date`: one date in 2099. Would be stopped by a 'not in the future' test on the date.
- `orphan_foreign_key`: one reference to a parent that does not exist. Would be stopped by `relationships` to the parent model.
- `replayed_row_new_key`: one event re-ingested under a new key. Would be stopped by uniqueness on a natural key or the upstream event id, not only the surrogate key.
- `amount_off_by_10x`: one amount off by a factor of 10. Would be stopped by a per-row comparison with that customer's or product's history, or a batch total vs recent batches.
- `stale_batch`: last year's file reloaded (dates -365 days). Would be stopped by a freshness test: the newest date must be within N days of the load.
- `empty_batch`: the whole batch arrives empty. Would be stopped by a minimum row count.
- `truncated_batch`: 90% of the batch is missing. Would be stopped by a minimum row count, or a row count compared with recent batches.
